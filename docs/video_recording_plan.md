# 演示视频录制筹划（Windows 自带录屏 · 3-5 分钟）

目标：一段 3-5 分钟的演示视频（README 承诺"含失败案例"），覆盖
"场景 → 求解 → 三方法对比 → 独立校验 → 导出"主线，以及"基线暂不可行"
失败案例与"放宽版可解"的反转，展示 AI 约束确认与双模式切换。

## 一、录制前准备（一次性，约 10 分钟）

1. **确认服务**：浏览器打开 `http://127.0.0.1:8000`，能进入工作台、
   场景列表能刷出 47 个场景（39 原始 + 8 个 `-loose` 放宽版）。
   服务没在跑就先：
   ```bat
   cd 城配调度副驾
   .venv\Scripts\python.exe scripts\serve.py
   ```
2. **打开 Game Bar 录屏**：设置 → 游戏 → Xbox Game Bar → 打开；
   设置 → 游戏 → 摄像 → 视频帧率 60、视频质量"标准或高"。
   - 开始/停止录制：**Win + Alt + R**；麦克风开关：**Win + Alt + M**
     （需要口播就保持开，Game Bar 悬浮条能看到麦克风电平）；
   - 文件保存在 `此电脑 → 视频 → 捕获`（Captures），mp4 格式。
   - 备用（Win11）：截图工具 Win+Shift+S → 切"录像"模式，可框选区域。
3. **桌面净化**：开专注助手（设置 → 系统 → 通知 → 勿扰），退出
   微信/QQ/邮件等弹窗源；桌面只留浏览器；浏览器只开一个标签页并
   **F11 全屏**；缩放建议 110%-125%（投影/手机端看得清）。
4. **预演一遍**：按下文分镜完整走一遍操作（不录），确认每步点击位置
   和预期画面，避免正式录时找按钮。

## 二、分镜脚本（建议每幕单独录一个文件，后期拼接）

> 红线（口播禁用词）：不说"严格 60 秒同预算"（本轮软预算）；不说
> "证明最优"（OR-Tools 可行≠最优）；不说"问题不可行"（除非 COPT
> MIP_INFEASIBLE 且限定当前模型）；不报人民币节约（只说"模型行驶秒"）；
> Mock 模型与合成插单事件要主动声明。

| 幕 | 时长 | 画面操作 | 口播要点 |
|---|---|---|---|
| 1 开场 | 20s | 首页全貌扫一眼（场景列表三列） | "这是一个城配调度副驾：出车前临时加单，怎么以最小改动把新单塞进已下发的计划。" |
| 2 数据与钩子 | 30s | 列表里指向 8 个黄色"基线暂不可行"；再指向 8 个绿色 `-loose` 场景及其参考成本列 | "47 个场景来自 Solomon/Kilby 双基准，参考成本进页面即可见；黄色这 8 个先埋个钩子，后面讲为什么。" |
| 3 主线求解 | 100-120s | 选 `c101-s101`（已生成，v3）→ 跑**低扰动**（约 1-2 秒出解）→ 展开"决策过程"面板（大白话、成本上限算式、候选对比）→ 切三方法对照/时刻表 → 指出"独立校验通过"标识 → 导出 CSV 点一下 | "新单是合成插单事件，大模型只出草案、人工确认才生效；每个结果都经独立校验器重算，不采信求解器自称；成本单位是模型行驶秒，不是人民币。" |
| 4 失败案例+反转 | 60-75s | 点开 `c101-s102`：显示"基线暂不可行"→ 切到 `c101-s102-loose` → 生成基线（秒出，参考成本 31130）→ 跑低扰动成功 | "刚才黄色的场景不是 bug：它的时间窗比装卸货时间还窄，老订单自己都排不出合法计划——300 秒诊断证据在 reports/baseline300。把时间窗放宽到合理紧度（-loose 版），基线 8/8 生成、插入法和低扰动 8/8 可行。" |
| 5 AI 约束与双模式 | 45-60s | 页头切换通俗演示版/专业审查版各停 5 秒；进约束草案：输入"o1 不能换车，必须还是 V1 送"→ 展示草案（硬约束/偏好、原文依据）→ 逐项确认 | "现在演示模式用的是规则提取器，接真实大模型时同一套人工确认流程；通俗版给外行看决策过程，专业版给审查者看原始编号和诊断 JSON，两者读的是同一份数据。" |
| 6 收尾 | 25s | 回到列表或评测报告页面滚一下 | "三方法同输入同预算对比、失败样本如实进报告不改分母；全部代码、冻结评测和审查脚本在 GitHub 仓库，README 有运行说明。" |

## 三、录制与后期

1. **分段录**：每幕一个文件（Win+Alt+R 开始/结束），说错或操作失误只重录该幕；
   每幕开头停顿 2 秒再开口，方便剪接。
2. **回放检查**（每幕录完立刻看）：声音清楚、字号可读、**无敏感信息入镜**
   （.env、密钥、个人路径）；数字口播与屏幕显示一致。
3. **拼接**：用 Win11 自带 Clipchamp（或"照片"App）按幕顺序拼接，
   导出 1080p mp4；命名为 `城配调度副驾_演示视频.mp4`。
4. **字幕（可选但推荐）**：至少给两处加文字标注——"单位：模型行驶秒，
   非人民币""黄色场景根因见 reports/baseline300"，防止静音观看误读。
5. **上传与填写**：传网盘（百度/阿里云盘），README 的"视频演示（待填写）"
   替换为链接+提取码，并确认链接在**整个评审期内有效**（提交要求明示）。

## 四、时间预算

准备 10 分钟 + 录制（6 幕 × 约 2 遍）40-60 分钟 + 拼接字幕 30 分钟 +
上传填写 10 分钟 ≈ **1.5-2 小时完工**。
