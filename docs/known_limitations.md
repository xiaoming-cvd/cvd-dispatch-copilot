# 已知限制（阶段 7 交付，诚实声明）

## 评测口径

- **60 秒软预算**：求解器时间限制为软上限、无进程硬截断。主比较 8 行
  端到端微超 60000ms（≤60.062s）；COPT dev 诊断 11 行 62.5–77.3s，
  属秒级越界（非毫秒误差），已单独成节披露。**不得宣传为严格同预算**；
  进程级硬截止为下一版工作。
- 冻结性质：本轮清单开跑前冻结，但每场景草稿哈希为**事后归档校验**
  （开跑后补记）；下一轮将开跑前写入不可变 manifest 再跑。
- 300 秒 COPT 诊断未执行（待指定 3 个代表性 dev 大场景，单独成表）。

## 算法能力边界（不按节点数简单划界）

- 大规模（kilby 75+ 节点）与紧时间窗（R 系列）场景：insert/rebuild 常
  毫秒级返回 NO_FEASIBLE_FOUND（≠不可行）；COPT 60s 无 incumbent。
  18 单的 r201-s101 亦出现 insert/rebuild 未找到解——适用边界由数据族 +
  约束特征共同决定（见报告分层可行率表）。
- 低扰动大型场景用满约 60 秒（候选池持续改进），**演示必须同时展示
  等待时间与成本**。
- 8 个场景在原计划物化阶段失败（20s 预算耗尽，E_PLAN_NOT_FOUND，
  ≠不可行）；构造器诊断与预注册复测为后续工作。
- 配对样本少：测试集 insert×rebuild 双双可行仅 2 个样本，成本结论
  仅限配对子集，不得推断总体节约。
- r202-s102 的不可行为"COPT 对当前 MIP 模型报告 MIP_INFEASIBLE"，
  仅针对该输入与建模。
