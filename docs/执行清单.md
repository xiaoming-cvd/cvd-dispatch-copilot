## 2. 分阶段执行清单

### 阶段 0 · 工程骨架与数据契约
- **过程边界**：只做骨架。不做网页、不做模型 API、不做公开数据下载、不做算法效果。
- **工作内容**：检查目录与 Python 环境，选定并锁定兼容依赖版本（requirements 锁定）；建模块目录（domain / adapters / solver / validation / api / llm / evaluation / frontend / tests / data / docs / reports）；实现 Scenario、Order、Vehicle、OriginalPlan、Locks、SolveResult 的 Pydantic 模型并导出 JSON Schema；输入校验、输入哈希、不可变版本号；建 3–8 任务小样本（含一个已知可行原计划）；README、.env.example、.gitignore、pytest 入口。
- **达成效果（验收）**：干净环境安装依赖后可跑通全部阶段 0 测试；schema 文档与代码一致；重复 ID、负数、单位冲突、矩阵维度错误、时间窗倒置等坏数据均有明确报错；密钥不出现在仓库；已有文件未被意外覆盖。
- **产物**：代码骨架 + Pydantic 模型与 JSON Schema + 校验器 + 小样本 + 锁定依赖 + README/.env.example/.gitignore + pytest 日志 + `docs/handoff.md`。

### 阶段 1 · 数据适配与情景生成
- **过程边界**：先合成样本，再接入 Solomon；Amazon 只小范围适配不阻塞主线；不下载大数据、不改原始文件。
- **工作内容**：Solomon 解析器 + 统一转换（保留原始载荷/时间单位）；字段映射与数据清单；固定种子的情景生成器——按基础算例划分开发集/测试集（同算例的裁剪/扰动版本不跨集）→ 选已知任务 → 冻结 → 揭示新增任务；保存新增任务列表、随机种子、事件日志（此阶段可保存"待生成原计划"的场景，原计划由阶段 2 生成）；Amazon 字段映射与小样本解析测试（未取得真实样本时标注合成结构样本）；数据质量报告。
- **达成效果（验收）**：来源与合成字段可追踪；样本通过 schema 校验；数据许可状态有记录；同种子结果可复现；测试集不被调参读取。
- **产物**：解析器/转换器/生成器代码、转换命令、数据清单 manifest、≥1 个规范场景 JSON、数据质量报告、测试日志、`docs/handoff.md`。

### 阶段 2 · 独立校验与可运行基线
- **过程边界**：命令行可用即可，不要网页、不要大模型。原计划仅由"当时已知任务"生成，冻结后才加新任务。
- **工作内容**：独立 validator（依据输入矩阵重算到达/装载/等待/服务开始/离开/返回时刻，查唯一覆盖与锁定，不调用求解器内部结论，关键规则有可手算预期测试）；原计划生成；简单插单基线（枚举插入、不搬旧任务、不漏单）；OR-Tools 完全重排基线；严格区分 invalid_input / feasible / no_feasible_found / proven_infeasible / error；命令行入口输出规范 JSON + 逐站时刻表 + 校验报告；演示成功插单、容量明显不足、锁定冲突、短预算未找到解各一次。
- **达成效果（验收）**：可行结果均经独立复核；拒绝漏单；返回时间与等待正确；超时未被写成"证明无解"。
- **产物**：validator、两基线、CLI、4 个演示案例的输入/结果/运行命令全保存、测试日志、`docs/handoff.md`。**→ 审查点 1**

### 阶段 3 · 低扰动重排与差异解释
- **过程边界**：前置验收 = 阶段 2 两基线与校验器通过；不声称"最佳已找到 = 全局最优"；不用软惩罚绕开硬约束。
- **工作内容**：低扰动候选生成器（可行插单 + 有限移位/交换/局部修复，OR-Tools 可辅助但不得宣称原生优化自定义扰动指标）；实现换车数（只统计旧任务）与旧相邻关系破坏数（新任务索引顺延不计扰动）的精确定义与计算；最低成本候选 + 成本上限（默认最佳可行成本 110%，可调并写入输出）内低扰动候选的选择；逐任务 diff（原车辆/新车辆/原相邻关系/新关系/变更原因，解释全部来自程序结果）；测试覆盖无新增任务、只插不换序、跨车移动、硬锁保持。
- **达成效果（验收）**：扰动指标不虚增；候选全可行；预算与配置可追踪；三种方法同输入原始指标并列展示，不预设谁胜。
- **产物**：低扰动求解器、扰动指标模块、diff 模块、对比演示与指标、测试日志、`docs/handoff.md`。**→ 审查点 2**

### 3. 低扰动算法计算预算口径（阶段 3 开工前锁定）

- "最佳已找到可行成本"指**低扰动方法在本次运行中自己找到的候选里的最低可行成本**（候选池含可行插单 + 移位/交换/局部修复产物）；
- 若低扰动生成过程调用完全重排（COPT/OR-Tools）作为种子或对照，**该子求解耗时计入本方法总预算**；评测时每种方法报告各自的端到端耗时（含子调用），同口径对比；
- 110% 成本上限基于上述"最佳已找到"值，配置写入输出；敏感性分析在开发集做，测试集只用冻结配置；
- 不声称"最佳已找到 = 全局最优"。

### 4. 数据许可与尺度（已落实）

- 许可状态全部改为"链接 + 待确认"标注，不再以"学术基准惯用"作为授权依据（见数据策略表）；
- ×60 为**模拟尺度转换**（1 原始单位 = 60 模拟秒），不代表真实配送分钟，已写入质量报告；
- **布局感知划分**：坐标集合相同的算例视为同一泛化单元整组划分（C101/C102、R101–R202 等各组不跨开发/测试），质量报告含布局分组表，回归测试防泄漏。
