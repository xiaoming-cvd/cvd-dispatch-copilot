# 算法规则与状态语义（阶段 7 交付）

## 三方法定义（同输入、同预算、独立校验）

| 方法 | 规则 | 适用定位 |
|---|---|---|
| insert 插单基线 | 枚举新单插入位置（队首/队尾/两旧任务之间），**不搬动旧任务**，旧序列视为固定槽位 | 快速基线；大规模/紧时间窗常快速返回未找到解 |
| rebuild 完全重排 | 全部订单重新优化。默认 OR-Tools（COPT 8.0.6 可选，须显式指定） | 质量基线；不保证最优（OR-Tools 可行 ≠ 证明最优） |
| low_disruption 低扰动 | 可行插单种子 + 单任务搬动/交换/局部修复生成候选池，按（换车数, 相邻破坏数, 成本）字典序选择，成本上限内筛选 | 产品主方法：在可接受成本内最小化对原计划的扰动 |

## 低扰动成本上限（重要口径）

- 业务上限 = `cost_cap_ratio × reference_best_cost`。
- 参考链（优先级从高到低，2026-10-12 队长决策修订）：
  1. **跨方法已验证方案**的最低成本（`reference_results`，冻结评测口径）；
  2. **baseline 原计划成本**（Web 任务链路显式开启
     `use_baseline_reference=True`；容缺口径——原计划只含旧订单，
     逐路线独立重算，任一路线违规则该参考不可用；`reference_source=
     "baseline"`。语义：新计划总时间 ≤ 比例 × 原计划总时间，口径偏紧，
     超限时如实标注）；
  3. 回退为候选池最优并标注 `pool_fallback`（池内参考，非跨方法参考）。
  `use_baseline_reference` 默认 False：冻结评测（`scripts/run_evaluation.py`）
  语义不变，历史结果可复现。
- 上限内无候选：推荐池内最低成本候选，`solver_status=
  no_candidate_within_cost_cap`，`within_cap=FALSE`（机器可读），
  **不计入达标可行率**。
- 固定候选池敏感性实验（`scripts/run_sensitivity_fixedpool.py`）：同池仅
  改筛选阈值；cap 放宽 ⇒ 可选集合单调增大，选中成本按扰动优先规则
  **不保证单调**。

## 扰动量化（src/solver/diff.py、perturbation.py）

- 旧任务换车数：新旧方案中旧任务车辆归属变化计数。
- 旧相邻关系破坏数：任务书定义的相邻关系（同车顺序相邻）在新方案中被
  打断的计数；**新增任务引起的索引移动不计入**。

## 状态语义（红线）

- `TIMEOUT / NO_FEASIBLE_FOUND ≠ 不可行`：毫秒级返回表示算法快速判定
  无可行解。
- 仅 COPT 对当前 MIP 模型报告 `MIP_INFEASIBLE` 时可写"证明不可行"，
  不得扩展为原始业务问题不可行。
- 可行性一律由独立校验器依据输入矩阵重算复核，不采信求解器标志。
